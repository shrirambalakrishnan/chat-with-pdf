# Chat with PDF

Upload your PDF and chat with it!

Answers to your questions will be grounded to the document you have uploaded!

## Setup

### Prerequisites

- Node **v26.2.0** and npm **11.13.0** (enforced — `npm install` fails on other versions)
- A GCP project with:
  - a Cloud Storage bucket
  - a Firestore database
  - a service account with object read/write/delete on the bucket and Firestore read/write

```sh
nvm use        # picks v26.2.0 from .nvmrc
npm install
```

### Service account key

Download a JSON key for the service account from the GCP console and save it at the repo root as
`service-account-key.json`. This file is gitignored — never commit it.
`service-account-key.example.json` shows the expected shape.

### Environment variables

Copy `.env.example` to `.env` and fill in every value:

| Variable | Description |
| --- | --- |
| `GCP_PROJECT_ID` | GCP project id |
| `GCS_BUCKET_NAME` | Cloud Storage bucket name |
| `FIRESTORE_DATABASE_ID` | Firestore database id (`(default)` for the default database) |
| `GOOGLE_APPLICATION_CREDENTIALS` | Path to the service account key file, e.g. `./service-account-key.json` |
| `PORT` | Optional, defaults to `3000` |

The service refuses to start if any required variable is missing, and names the missing ones.

### Run

```sh
npm start      # run the server
npm run dev    # run with auto-restart on file changes
```

Check it is up:

```sh
curl http://localhost:3000/health   # {"status":"ok"}
```

## Data model

### `users` collection

| Field | Type | Notes |
| --- | --- | --- |
| document id | string | Fixed for the seed user (from the seed config file), auto-generated for real users later. Not duplicated as a field. |
| `name` | string | |
| `email` | string | |
| `createdAt` | timestamp | Set by the server when the document is created |

### `documents` collection

Document ids are auto-generated by Firestore.

| Field | Type | Notes |
| --- | --- | --- |
| `ownerId` | string | id of the user in `users` |
| `filename` | string | original name supplied by the client |
| `contentType` | string | `application/pdf` |
| `size` | number | bytes, as declared by the client |
| `gcsUri` | string | `gs://{bucket}/documents/{documentId}.pdf` (the bucket is private) |
| `status` | string | `pending_upload` → `uploaded` → `processing` → `ready`, or `failed` |
| `error` | string or null | reason, when status is `failed` |
| `createdAt` | timestamp | server time |
| `updatedAt` | timestamp | server time |

## Seed user

Until auth exists, every document belongs to a single seed user. Its `id`, `name` and `email` live in
`scripts/seed-user/seed-user.json`. That file is for seeding only — application code reads users from
Firestore, never from this file.

With `.env` and the key file in place, create the seed user:

```sh
npm run seed:user
```

This creates `users/{id}` using the `id` from the config file as the document id. It is safe to re-run:
if the user already exists it is left unchanged.

## API

Until auth exists, the caller is identified by the `X-User-Id` header, which must match a document in
the `users` collection (e.g. the seed user).

### `POST /documents`

Asks for permission to upload one PDF. Creates a `documents` record with status `pending_upload` and
returns a signed URL; the client then uploads the file directly to Cloud Storage.

Request body:

| Field | Type | Rules |
| --- | --- | --- |
| `filename` | string | required |
| `contentType` | string | must be `application/pdf` |
| `size` | number | bytes, 1 to 20 MB (20971520) |

```sh
curl -X POST http://localhost:3000/documents \
  -H 'Content-Type: application/json' \
  -H 'X-User-Id: seed-user' \
  -d '{"filename": "report.pdf", "contentType": "application/pdf", "size": 123456}'
```

Response `201`:

```json
{
  "documentId": "AbC123...",
  "uploadUrl": "https://storage.googleapis.com/<bucket>/documents/AbC123....pdf?X-Goog-Algorithm=...",
  "uploadHeaders": {
    "Content-Type": "application/pdf",
    "x-goog-content-length-range": "1,20971520"
  },
  "expiresAt": "2026-01-01T00:15:00.000Z"
}
```

Errors:

| Status | When |
| --- | --- |
| `400` | missing or invalid body field, `contentType` is not `application/pdf`, or `size` is zero or over 20 MB |
| `401` | `X-User-Id` header missing |
| `403` | `X-User-Id` does not match a user |

#### Uploading to the signed URL

`PUT` the file to `uploadUrl` within 15 minutes, sending every header in `uploadHeaders` exactly as
returned. Cloud Storage rejects the upload if the content type differs or the file is over 20 MB.

```sh
curl -X PUT "<uploadUrl>" \
  -H 'Content-Type: application/pdf' \
  -H 'x-goog-content-length-range: 1,20971520' \
  --upload-file report.pdf
```

After the `PUT` succeeds, call `POST /documents/:id/complete`.

### `POST /documents/:id/complete`

Tells the service the upload has finished. The service verifies the stored file and updates the
document's status. No request body.

The stored file must:

- exist at the document's `gcsUri`
- be larger than zero and at most 20 MB
- have content type `application/pdf`
- start with the PDF signature `%PDF-`

| Case | Status | Effect on the record |
| --- | --- | --- |
| File is present and valid | `200`, returns the document | status → `uploaded`, `size` → actual object size |
| File is present but invalid | `422`, returns the reason | status → `failed`, `error` set, object deleted from the bucket |
| File is not in the bucket yet | `409` | unchanged (`pending_upload`): upload, then retry |
| Document is already `uploaded` or later | `200`, returns the document | unchanged |
| Document is already `failed` | `409` | unchanged: start again with `POST /documents` |
| `X-User-Id` header missing | `401` | unchanged |
| `X-User-Id` is not a user, or not the document's owner | `403` | unchanged |
| No document with that id | `404` | none |

```sh
curl -X POST http://localhost:3000/documents/<documentId>/complete \
  -H 'X-User-Id: seed-user'
```

Once a document is `uploaded`, it is picked up from Firestore by the (future) processing service.

### Walkthrough: upload a PDF end to end

Requires [`jq`](https://jqlang.org/). With the server running and the seed user created:

```sh
FILE=report.pdf
SIZE=$(wc -c < "$FILE" | tr -d ' ')

# 1. Ask for a signed upload URL
RESPONSE=$(curl -s -X POST http://localhost:3000/documents \
  -H 'Content-Type: application/json' \
  -H 'X-User-Id: seed-user' \
  -d "{\"filename\": \"$FILE\", \"contentType\": \"application/pdf\", \"size\": $SIZE}")
DOCUMENT_ID=$(echo "$RESPONSE" | jq -r .documentId)
UPLOAD_URL=$(echo "$RESPONSE" | jq -r .uploadUrl)

# 2. Upload the file straight to Cloud Storage
curl -X PUT "$UPLOAD_URL" \
  -H 'Content-Type: application/pdf' \
  -H 'x-goog-content-length-range: 1,20971520' \
  --upload-file "$FILE"

# 3. Confirm the upload; status becomes "uploaded"
curl -X POST "http://localhost:3000/documents/$DOCUMENT_ID/complete" \
  -H 'X-User-Id: seed-user'
```
